5. A cleaner phone-screen.tsx

The component is 1,645 lines and mixes the video stage, the tool row, the bottom dock, the fill layout and the input handling. The proposal splits it by job, with the same props at each boundary. Nothing is refactored yet.

Before
phone-screen.tsx (1,645 lines) ├─ stage sizing (ResizeObserver, fit box) ├─ video canvas + touch/pointer input ├─ fill layout and side rails ├─ nav row, tool row, device actions ├─ options popover, app shortcuts └─ macro dock, errors, stream status
After (proposed)
PhoneScreen (~150 lines, composes) ├─ usePhoneStage() size + fit box ├─ PhoneCanvas canvas + input ├─ PhoneRails volume / power ├─ PhoneToolRow nav + tools ├─ PhoneDock options, actions └─ PhoneStatus errors, loading
Order

Extract the pure parts first (fit box, sizing), then the input code, then the UI sections. Each step runs the e2e scripts.

Risk

Video and touch input. They stay in one module until the other parts are proven, and the Windows pack is tested on a real phone before merging.

Not included

No change to device control, macro runs or the agent API. Only file boundaries move.

Decision needed: split now (after the taskbar editor), or only when the next feature touches this file?
