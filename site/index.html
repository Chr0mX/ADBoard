What you can do

Every tab has its own page in the user guide.

Control

See each phone live, tap, swipe and type from your computer, or watch every phone in a grid. Saved app buttons open games and apps in one tap.

Manage

Reconnect, reboot, take screenshots, record the screen, read device information and pair phones over Wi-Fi.

Apps

Scan a phone to add its apps with their names and icons, sort them into categories, install APKs and clear or uninstall packages.

Files

Send files to a phone and fetch screenshots, recordings and downloads back to your computer.

Macros

Record finger taps and swipes with exact timing and replay them on many phones, on a schedule or from a queue.

Shell Automation

Build a list of actions — open an app, wait, screenshot, send a file, press a key, run a command — and run it on every phone you choose.

Developer

Run ADB shell commands, read the log and see full device details.

Hosts

Control phones plugged into other computers from the same dashboard.

Settings

Stream quality, keyboard, grid, sign-in, and your data folder with backups, export and import.

Your data stays yours

Macros, scripts and settings live in a data folder outside the app, so updating or reinstalling never touches them.

  • One file per macro and script. Plain JSON you can copy, back up or share.
  • Export and import. One item or the whole library, with a backup made first.
  • Never silently overwritten. Replaced and deleted files go to a backups folder.
  • No passwords in the files. The sign-in account is stored only as a salted hash.

How it works

scrcpy and ADB carry the video and input. ADBoard handles discovery, sessions and the web UI, so the browser never talks to ADB directly.

  1. Connect phones

    Plug Android phones into a Windows or Linux host over USB, or pair them with wireless ADB.

  2. Start ADBoard

    Run run.bat on Windows or adboard-agent on Linux. One binary serves the UI, video and control.

  3. Open the dashboard

    Open it in a browser at port 3848, or publish it behind Nginx Proxy Manager and Cloudflare with sign-in.

Quick start

No installer. One script downloads ADB and scrcpy; Windows and Linux run the same Rust binary.

Windows

git clone https://github.com/Chr0mX/ADBoard
cd ADBoard
powershell -ExecutionPolicy Bypass -File scripts\fetch-deps.ps1
run.bat

The script puts ADB and scrcpy in dist\windows\vendor; run.bat starts ADBoard.exe. Open http://127.0.0.1:3848.

Linux

git clone https://github.com/Chr0mX/ADBoard
cd ADBoard
make fetch-deps
cargo run -p adboard-agent --release

Needs a Rust toolchain. Serves the dashboard on port 3848. Try it without phones: ADBOARD_FORCE_MOCK=1.

Ready for remote access

Publish ADBoard on its own subdomain behind Nginx Proxy Manager with Cloudflare's proxy turned on.

  • Sign-in with a changeable password. Salted and hashed on the host; set it from the dashboard on your own network.
  • Locked by default. Requests through a proxy are refused until an account exists.
  • Stable live video. Keep-alive pings stay under Cloudflare's and nginx's idle limits.
  • Large uploads. APKs and files go up in chunks under Cloudflare's 100 MB request cap.
  • No secrets in URLs. Access tokens travel in headers, never in logs.
  • Clean updates. Cache headers keep Cloudflare from serving a stale dashboard.
