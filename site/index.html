ADBoard

Android device control

Control your Android phones from one page.

ADBoard runs on your own computer. It shows each phone's screen live and sends your touches and typing to it, one phone or many at a time.

What you can do

Each tab has its own page in the user guide.

Control

See each phone live and tap, swipe or type from your computer. Grid view shows every phone at once. Saved app buttons open apps in one click.

Manage

Reconnect, reboot, take screenshots, record the screen, read device details and pair phones over Wi-Fi.

Apps

Scan a phone to add its apps with their names and icons, sort them into categories, install APKs, and clear or uninstall packages.

Files

Send files to a phone and fetch screenshots, recordings and downloads back to your computer.

Macros

Record finger taps and swipes with their timing, then replay them on one phone or many, on a schedule or from a queue.

Shell Automation

Build a list of steps, such as opening an app, waiting, taking a screenshot, sending a file, pressing a key or running a command. Then run it on the phones you choose.

Developer

Run ADB shell commands, read the log and see device details.

Hosts

Control phones that are plugged into other computers, from the same page.

Settings

Stream quality, keyboard, grid, sign-in, and your data folder, with backups, export and import.

Your data stays yours

Macros, scripts and settings are stored in a data folder outside the app, so updates and reinstalls leave them alone.

  • One file per macro and script. Plain JSON you can copy, back up or share.
  • Export and import. One item or the whole library, with a backup made first.
  • Never silently overwritten. Replaced and deleted files go to a backups folder.
  • No passwords in the files. The sign-in account is stored only as a salted hash.

How it works

scrcpy and ADB carry the video and input. ADBoard finds the phones, manages the sessions and serves the web page. The browser never talks to ADB directly.

  1. Connect phones

    Plug phones into a Windows or Linux computer with USB, or pair them over Wi-Fi with ADB.

  2. Start ADBoard

    Run run.bat on Windows, or adboard-agent on Linux. One program serves the page, the video and the controls.

  3. Open the dashboard

    Open it in a browser on port 3848. You can also publish it behind Nginx Proxy Manager and Cloudflare, with a sign-in.

Quick start

There is no installer. One script downloads ADB and scrcpy, and Windows and Linux run the same Rust program.

Windows

git clone https://github.com/Chr0mX/ADBoard
cd ADBoard
powershell -ExecutionPolicy Bypass -File scripts\fetch-deps.ps1
run.bat

The script puts ADB and scrcpy in dist\windows\vendor; run.bat starts ADBoard.exe. Open http://127.0.0.1:3848.

Linux

git clone https://github.com/Chr0mX/ADBoard
cd ADBoard
make fetch-deps
cargo run -p adboard-agent --release

Needs a Rust toolchain. Serves the dashboard on port 3848. Try it without phones: ADBOARD_FORCE_MOCK=1.

Ready for remote access

Put ADBoard on its own subdomain behind Nginx Proxy Manager, with Cloudflare's proxy turned on.

  • Sign-in with a password you can change. It is salted and hashed on the host. Set it from the page on your own network.
  • Locked until you set a password. Requests through a proxy are refused until an account exists.
  • Video stays connected. Keep-alive pings stay under the idle limits of Cloudflare and nginx.
  • Large uploads. APKs and files are sent in chunks, so they stay under Cloudflare's 100 MB request limit.
  • No secrets in URLs. Access tokens travel in headers, not in the address.
  • Updates show up right away. Cache settings stop Cloudflare from serving an old copy of the page.
